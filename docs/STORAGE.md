# 存储与操作

## 数据布局

每块数据盘独立保存资源和索引，既有名称保持稳定：

```text
hifi-music-nano/
├── library-id
├── music/                       # 正式音频、标签和内嵌封面
├── resources/artists/            # 公共歌手资料与头像
├── manager/
│   ├── manager.db               # 曲库索引、草稿、清理与操作摘要
│   └── uploads/<owner-id>/       # 未导入原件及草稿封面
└── minimserver/<device-id>/      # 每设备独立的原生播放数据
```

设备配置和程序位于设备上。选盘结果按卷标识保存；盘离线时不在系统目录创建替代曲库。新盘初始化须确认，不格式化磁盘，不清理盘内其他文件。

`manager.db` 含不可重建的草稿编辑意图，不能当缓存删除。原始标签直接保存在歌曲记录，额外标签只用于手动编辑；已有记录仍可读取。操作摘要最多 99 条，不保存恢复副本。

## 提交边界

保存表单或确认导入、删除后直接提交，没有撤销或回收站。未提交的表单和选图可以取消。

- 标签与封面修改：校验当前文件，写入临时副本，验证音频摘要后替换。
- 导入：按所选歌曲逐首发布，独占目标文件名，不覆盖现有音乐。
- 删除：永久移除所选文件；分组草稿只处理自己的文件列表。
- 歌手资料：发布完整头像和资料后，释放旧头像。

批量操作不保证整体原子性。后续失败保留先前结果，剩余歌曲可继续处理。重启扫描实际正式音乐，恢复可继续操作的草稿状态，不自动重放删除或导入命令。

## 文件释放

| 资源 | 释放规则 |
| --- | --- |
| 正式音乐 | 用户确认删除，或编辑成功后原位替换 |
| 未导入原件 | 保留到对应歌曲成功导入或确认删除，不按年龄清理 |
| 已导入原件 | 发布并提交索引后立即释放，失败自动重试 |
| 草稿封面 | 保留当前引用，最后一首歌曲移出草稿后释放 |
| 临时文件及孤立上传 | 普通结束立即释放；中断遗留由启动及周期清理回收 |
| 已完成草稿 | 上传源清理完毕后删除记录，正式音乐不受影响 |

清理仅在项目定义的目录内执行，校验盘状态、目录句柄及文件类型，拒绝越界路径和符号链接。不递归删除整个上传所有者目录，避免误伤兄弟草稿。待清理路径只用于前向释放，不包含旧内容。
